# GLOW-37 authorization regression coverage

The `Database security / RLS and role authorization` pull-request job fails if source guards or real PostgreSQL authorization tests fail. It starts PostgreSQL 16 and creates a uniquely named disposable database for each run; an absent admin URL, invalid target, missing client, failed migration, skipped database setup, or failed test makes the job fail. The generated database is dropped in `finally`, including after subprocess timeout. No Supabase credentials or deployed data are used.

Run source checks with `node --test tests/rls-source-guards.test.mjs`. Run the database checks with `GLOWFLOW_RLS_ADMIN_DATABASE_URL` set to a loopback PostgreSQL URL whose database is `postgres`, then `node tests/rls-run.mjs`. Set `PSQL_BIN` when `psql` is not on PATH. Use a disposable local cluster: the dependency fixture creates the `anon`, `authenticated`, and `service_role` cluster roles if absent. Do not point this at a shared or production cluster.

The database suite applies the actual sandbox connections and reservation migrations over a minimal synthetic dependency fixture. It exercises owners, staff, anonymous users, an unrelated authenticated identity and a second tenant. It verifies owner-only reads, cross-tenant invisibility, forbidden browser-role writes, hidden event data, service-only RPC permissions and empty RPC search paths, alongside existing concurrent booking, idempotency and reconciliation checks.

A source check examines all checked-in public table declarations for RLS enablement and rejects later disablement. A separate client import graph check follows local alias and relative imports, re-exports and literal dynamic imports/require calls into the privileged Supabase helper. Explicit `use server` modules are server-action boundaries; Next.js also enforces the helper's `server-only` import during the production build. Regression fixtures demonstrate that violations fail the guards. These source checks are deliberately conservative and are not a general TypeScript or SQL parser.

## Remaining acceptance work

This does not claim executable role coverage for every historical tenant table. The legacy `supabase/schema.sql` contains malformed/duplicated bootstrap content, and historical migration ordering does not currently support a trustworthy fresh full-schema replay. Repair that bootstrap and expand real database role tests to all private and public tables before closing GLOW-37. Static RLS declarations do not establish correct policy behavior or public-field allowlists. Making this status a required merge check is a repository branch-protection setting, not changed by this workflow.
